# 🎬 Movie App — Full Technical Audit & Refactoring Roadmap

---

## Executive Summary

This is a **Flutter movie-browsing app** that consumes the TMDB API, built with a Clean Architecture skeleton + BLoC state management. The structural foundation is correct and the dependency chain (DataSource → Repository → UseCase → Bloc → UI) is in place. However the implementation contains a **critical functional bug** that makes the recommendations grid always show dummy data instead of real API results, **exposed API credentials** baked in source code, **broken `copyWith`** that cross-wires popular/now-playing state, and no meaningful tests. The project is a good learning exercise but is **not production-ready** in its current state.

|------|-------|

| Implementation correctness | 3/10 — critical bugs |
| Security | 1/10 — API key exposed in source |

## 3. Current Architecture

### Pattern: Clean Architecture (Partial)
The project follows a Clean Architecture skeleton with three layers:
- **Domain**: entities, abstract repository, use cases
- **Data**: models (extends entities), concrete repository, remote data source
- **Presentation**: BLoC controller, screens, components

The implementation is **structurally correct** but has bugs that undermine its integrity.

### State Management: `flutter_bloc` (BLoC pattern)
| BLoC | File | Manages |
|------|------|---------|
| `MoviesBloc` | `movies_bloc.dart` | Now Playing, Popular, Top Rated lists on home |
| `MovieDetailsBloc` | `movie_details_bloc.dart` | Movie detail + recommendations |

Both BLoCs are provided locally via `BlocProvider` inside their respective screen widgets.

### Navigation: Navigator 1.0 (imperative)
- `Navigator.push()` with `MaterialPageRoute` — used in `now_playing_component.dart` line 44–49
- **No named routes, no go_router, no deep-linking support**
- Two "See More" `InkWell` buttons in `movies_screen.dart` lines 43–44 and 82–83 have `TODO` comments and do nothing

### Dependency Injection
`GetIt` via a manually-called `ServicesLocator().init()` in `main()`.  
The global singleton `sl` is accessed directly from screen widgets (`sl<MoviesBloc>()` in `movies_screen.dart` line 17), coupling the UI layer to the DI container.

### Data Layer
- **HTTP client**: `Dio` — but **a new `Dio()` instance is created on every call** (lines 25, 41, 57, 73, 88 of `movie_remote_data_source.dart`). No shared instance, no interceptors, no token injection.
- **Serialization**: Manual `fromJson` factory constructors — no `json_serializable`
- **Local DB**: None
- **Caching**: `CachedNetworkImage` for images only; no API response caching

  │  user opens screen
  ▼

  ▼

  ▼

## 5. Problems Found

### 🔴 CRITICAL

---

**P-01** | **Critical** | `lib/movies/data/repository/movies_repository.dart` lines 18–28 (and all 5 methods)

**What's wrong:** The `try/catch` block is placed *after* the await — it will never catch exceptions thrown by `baseMovieRemoteDataSource`. The awaited call is *outside* the try block; if it throws, the exception propagates uncaught and crashes the app.

```dart
// BROKEN — exception from this line will NOT be caught:
final result = await baseMovieRemoteDataSource.getNowPlayingMovies(); // ← throws here
try {
  return Right(result); // ← try starts too late
} on ServerException catch (failure) { ... }
```

**Why it matters:** Every API error (network down, bad key, 404) will cause an unhandled exception and crash the app instead of displaying a friendly error message.

**How to fix:** Wrap the entire method body in `try/catch`:
```dart
try {
  final result = await baseMovieRemoteDataSource.getNowPlayingMovies();
  return Right(result);
} on ServerException catch (failure) {
  return Left(ServerFailure(failure.errorMessageModel.statusMsg));
}
```

---

**P-02** | **Critical** | `lib/movies/presentation/screens/movie_detail_screen.dart` line 274

**What's wrong:** `_showRecommendations()` uses `recommendationDummy.length` (from the dummy file) as `childCount` instead of `state.recommendation.length`. The grid always shows 13 hardcoded dummy images in production, never real recommendations.

```dart
childCount: recommendationDummy.length,  // ← ALWAYS 13 dummy items
```

**Why it matters:** This is a silent functional bug — the app appears to work but shows fake data to users.

**How to fix:** Replace with `state.recommendation.length` and remove the import of `dummy (1).dart`.

---

**P-03** | **Critical** | `lib/core/utils/app_constances.dart` lines 2–3

**What's wrong:** The TMDB API key `ce8786bc57ceba7a6510bb73fe732506` is hardcoded as a plain `static const String` in source code.

**Why it matters:** If this repository is ever pushed to GitHub (public or private with a breach), the key is permanently exposed in git history. The key can be rotated by TMDB but the code is still wrong practice.

**How to fix:** Use `--dart-define` at build time and read via `String.fromEnvironment('TMDB_API_KEY')`, or use a `flutter_dotenv` package. Never commit secrets.

### 🟠 HIGH

---

**P-04** | **High** | `lib/movies/presentation/controller/movies_states.dart` lines 42–44

**What's wrong:** `copyWith` has a logic bug — it cross-wires fields:
```dart
popularMessage: popularMessage ?? this.nowPlayingMessage,  // ← should be this.popularMessage
popularMovies: popularMovies ?? this.nowPlayingMovies,     // ← should be this.popularMovies
popularState: popularState ?? this.nowPlayingState,        // ← should be this.popularState
```

**Why it matters:** When only `popularMovies` is updated, the `popularMessage` and `popularState` reset to the now-playing values. This causes the Popular section to display incorrect loading/error state.

**How to fix:** Fix each fallback to reference its own field (`this.popularMessage`, `this.popularMovies`, `this.popularState`).

---

**P-05** | **High** | `lib/movies/data/datasource/movie_remote_data_source.dart` lines 25, 41, 57, 73, 88

**What's wrong:** `new Dio()` is instantiated fresh on every network call. No shared Dio instance, no base options, no interceptors, no timeout configuration.

**Why it matters:** Performance overhead; impossible to add auth headers, logging, or retry logic globally; no request timeout means calls can hang indefinitely.

**How to fix:** Create a single `Dio` instance in the DI container with `BaseOptions` (baseUrl, connectTimeout, receiveTimeout) and inject it.

---

**P-06** | **High** | `lib/movies/presentation/screens/movie_detail_screen.dart` lines 77, 253

**What's wrong:** Unsafe `!` (bang operator) on nullable fields:
- Line 77: `state.movieDetails!.backdropPath!` — both `movieDetails` and `backdropPath` could be null
- Line 253: `recommendation.backdropPath!` — `backdropPath` on `Recommendation` is `String?`

**Why it matters:** `Null check operator used on a null value` will crash the app if TMDB returns a movie without a backdrop image (common for less-popular movies).

**How to fix:** Use null-aware operators and fallback images:
```dart
imageUrl: ApiConstance.imageUrl(recommendation.backdropPath ?? '/placeholder.jpg')
```

---

**P-07** | **High** | `lib/movies/data/models/movie_model.dart` line 17 and `lib/movies/domain/entites/movie.dart` line 10

**What's wrong:** `backdropPath` is typed as non-nullable `String` but `backdrop_path` can be `null` in TMDB responses. `fromJson` does `json["backdrop_path"]` without null check → crashes on movies without backdrop.

**Why it matters:** App crashes parsing list responses if any movie lacks a backdrop.

**How to fix:** Make `backdropPath` nullable (`String?`) in the entity and model, and handle in UI.

---

**P-08** | **High** | `lib/movies/presentation/components/popular_component.dart` line 81 AND `lib/movies/presentation/components/top_rated_component.dart` line 81

**What's wrong:** Both error state widgets display `state.nowPlayingMessage` instead of their own message:

- `top_rated_component.dart` L81: `Text(state.nowPlayingMessage)` → should be `state.topRatedMessage`

**Why it matters:** Users see the wrong error message; the Popular error shows the Now Playing error text.

## 6. Recommended Target Architecture

### Proposed Architecture: Clean Architecture + BLoC (enhanced)

**Justification:** The existing skeleton is already Clean Architecture + BLoC. The team invested in this direction; abandoning it would waste what works. The recommendation is to **fix and complete** the existing architecture rather than replace it.

Specific improvements:
- Replace `dartz` → `fpdart` (same Either pattern, maintained)
- Add `go_router` for declarative routing (enable deep links and "See More" screens)
- Add `flutter_secure_storage` or `--dart-define` for secrets
- Add `dio_cache_interceptor` or `hive` for API response caching
